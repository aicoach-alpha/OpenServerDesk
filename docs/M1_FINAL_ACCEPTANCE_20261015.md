## Four unresolved M1.5 release blockers

1. **Full runnable product payload:** the .deb bundles only Gateway,
   MessageBus, UserService and a staging-only read-only API. It does not
   provide complete app management, local storage, or dashboard replacement.
2. **In-place activation and rollback:** `migrate_installer.py` explicitly
   leaves activation and rollback unimplemented; staging fixture recovery is
   not a cutover controller for actual CasaOS.
3. **Real application data:** external Docker bind mounts, Compose apps
   and data beyond the present backup scope lack a comprehensive verified
   backup → restore → application reactivation migration contract.
4. **Production release integrity/security:** no verified signed full
   production release and no independent completed security/pentest acceptance.

## Release disposition

Keep CasaOS in place and fully operational; do not change M1 readiness
or claim automatic migration is safe. Completing M1 requires implementing
the four missing product/release capabilities as a coherent deliverable
and repeating the **final release acceptance**, not reopening earlier
synthetic fixtures without a specific failure.
